# 为什么钉死版本**并**钉死哈希（`--require-hashes`）：
#
#   这个作业的全部结论都是「两套独立实现逐字节相符」。它与其它作业的区别在于：
#   另一套实现跑在本仓之外（Python 的 argon2-cffi / cryptography）。
#   依赖一旦浮动，红与绿的原因就不再是「我们改坏了什么」，而是「上游改了实现」——
#   而 argon2 / AES-GCM 的输出**不因实现不同而不同**，所以那种红只会是
#   「取到了一个改过算法或改过打包的上游」，正是最需要拦下的一类变化。
#
#   只钉版本不够：版本号相同、内容被换掉（重新上传 / 镜像投毒）无法察觉。
#   哈希把「这一份字节」也钉死了。
#
# 覆盖范围：sdist + manylinux x86_64 轮子 + win_amd64 轮子。
#   CI（ubuntu-latest）与本机（Windows）都落在这三类里。
#   换平台（如 macOS arm64）或换 Python 次要版本时，pip 会报
#   "THESE PACKAGES DO NOT MATCH THE HASHES" —— 这是**预期行为**，不是坏了：
#   按报错信息里的期望哈希补一行 `--hash=` 即可（补哈希的动作会出现在 diff 里，
#   那是本文件刻意要留下的摩擦）。
#
# 安装：
#   python -m pip install --require-hashes -r tools/ci/requirements.txt
#
